### 2.3.2：单向与双向策略对比（v1.1）

```powershell
python code/quiz1/v1.1.py
```

程序在同一批地图上运行以下四种策略，共 **39×4＝156** 个组合：

| 图表标记        | 正向策略              | 反向策略              |
| --------------- | --------------------- | --------------------- |
| A* Manhattan    | 曼哈顿 A*             | 无                    |
| Bi-A* Manhattan | 曼哈顿 A*，目标为终点 | 曼哈顿 A*，目标为起点 |
| A* + Dijkstra   | 曼哈顿 A*             | Dijkstra              |
| A* + BFS        | 曼哈顿 A*             | BFS                   |

双向策略从正向开始，每侧交替扩展一个有效节点。堆统一按 `(f, g, 坐标)` 排序，
BFS 使用 FIFO 队列，邻居顺序均为上、下、左、右。首次相遇仅更新完整路径候选代价 `mu`；
当 `mu <= max(Lf, Lb)` 或一侧队列耗尽时结束，`Lf`、`Lb` 是两侧有效队首给出的下界。

### 2.5：理解测量口径

- 每个组合先预热一次，再按固定种子打乱算法顺序重复测量。
- 扩展节点数只计有效非终点节点实际遍历邻居的次数，排除过期条目；双向取两侧之和，同一坐标被两侧扩展时计两次。
- 弹出次数包含过期条目；前沿峰值是队列或堆的最大长度，双向记录两侧长度之和的最大值。
- 耗时包含搜索、统计与路径恢复，双向还包含相遇检测及拼接；输入加载、独立校验、绘图及测量前的垃圾回收不计入。
- 峰值内存用 `tracemalloc` 单独测量，包含搜索结构和返回路径，不含预加载地图，不等同于进程总内存。
- 时间和内存先取每张地图重复测量的中位数，再对各地图取算术平均；扩展节点数直接跨图平均。
- 每次运行都用独立 BFS 校验最短距离与路径合法性，并检查结果稳定性和输入未被修改。

固定种子保证输入地图一致；耗时与内存仍受 Python 版本及运行环境影响。
性能比较应优先使用同一次评测中的结果，并结合分组表分析，避免仅凭总体平均判断所有地图场景。

## 3. quiz2：加权地形最小代价搜索

### 3.1：准备加权地形地图

```powershell
python code/quiz2/generate_map.py
```

脚本生成同目录的 `map`，沿用 Quiz1 的 `cases`、`start`、`end`、`grid` 格式，共 **105 张地图**，
其中 74 张可达、31 张无解。包含题目示例、均匀权重 1/2/3、直走昂贵而绕路更便宜、强制绕行、
隔墙无解，以及三个规模下的随机地图。随机配置完整组合三组地形权重 `1/3/8`、`2/5/9`、`3/6/9`，
三档障碍概率 0%、15%、30% 和三个固定种子；另含相邻免费终点、起终点重合、单行、零地形和最小无解用例。

数字字符表示进入该格子的代价，`X` 为障碍，进入终点代价为 0；起点初始不收费，若再次进入起点，
采用每张地图的 `start_terrain_cost`。起终点重合时只保留 `S`，以坐标判断终点。

`expected.minimum_cost` 是独立 Dijkstra 计算的参考答案，无解为 `-1`；
`steps_among_minimum_cost_paths` 是所有最小代价路径中的最少步数，
`shortest_steps_ignoring_weights` 是忽略权重后的最少步数，可用于观察最少步数与最低代价的差异。
`min_non_goal_cost` 记录非终点的最小进入代价，包含起点的再次进入代价。
参考答案仅用于校验；算法应从地图本身计算启发函数所需的地形信息。

### 3.2.1：运行加权地形评测（v2.0）

```powershell
python -m unittest discover -s code/quiz2 -p "test*.py"
python code/quiz2/v2.0.py
```

程序读取 `code/quiz2/map`，在 105 张地图上运行三种算法，共 **315** 个评测组合：

| 图表标记     | 算法            | 启发函数                                                        |
| ------------ | --------------- | --------------------------------------------------------------- |
| Dijkstra     | 迪杰斯特拉      | `0`                                                           |
| A* corrected | 修正曼哈顿 A*   | 非终点权重至少为 1 时使用 `max(d-1, 0)`；存在零权时使用 `0` |
| A* scaled    | 最小权重缩放 A* | `c_min * max(d-1, 0)`                                         |

`d` 为到终点的曼哈顿距离，减去 1 对应最后进入终点免费的一步。
`c_min` 从输入地图计算，不读取参考答案；当 `c_min=0` 时，缩放 A* 退化为 Dijkstra。
当 `c_min=1` 时，两种 A* 的搜索行为相同。题目函数接口为
`a_star(start, end, grid, start_terrain_cost=1)`，返回最小总代价，无解返回 `-1`。

支持 `--map`、`--output`、`--repeats`、`--memory-repeats`，例如：

```powershell
python code/quiz2/v2.0.py --map code/quiz2/map --output result/quiz2 --repeats 7 --memory-repeats 3
```

测试使用独立 Bellman-Ford 对照小地图穷举与随机加权地图，覆盖免费终点、零代价格子、起终点重合、
无解、单行累计代价、低价绕路、启发一致性与终点不计扩展等情况。

### 3.2.2：地标启发拓展（v2.1）

```powershell
python -m unittest discover -s code/quiz2 -p "test*.py"
python code/quiz2/v2.1.py
```

仍使用同一批 105 张地图，比较四组策略，共 **420** 个组合：

| 图表标记   | 启发函数                       |
| ---------- | ------------------------------ |
| Dijkstra   | `0`                          |
| A* scaled  | `c_min * max(d-1, 0)`        |
| ALT A* (2) | 缩放下界与两个地标下界取最大值 |
| ALT A* (4) | 缩放下界与四个地标下界取最大值 |

#### 地标及有向距离

按地图内部四分位附近的左上、右下、右上、左下锚点依次选取可通行格；锚点遇障碍时，选择最近的
未选格，同距按坐标排序。选点只使用可通行布局，不针对查询起终点；2 地标组使用 4 地标组的前两个。
不足四个可通行格时使用实际可选数量，明细表同时记录请求数量、实际数量及坐标。

每个地标分别在原图和反向图上运行 Dijkstra，计算 `d(L,n)` 与 `d(n,L)`。原图 `u→v` 的代价是进入 `v`
的权重，因此反向 `v→u` 仍收取 `v` 的权重。地标启发采用：

```text
h(n) = max(缩放下界, 0,
           d(L,t) - d(L,n),
           d(n,L) - d(t,L))   # 对每个地标取上述两项
```

只有两个距离均有限时才使用对应差值项。距离表使用当前终点免费的同一张有向图，不套用无向图的
绝对值公式；地标预处理不读取 `expected`。查询仍使用统一的 `(f,g,坐标)` 平局规则和上下左右邻居顺序。

支持 `--map`、`--output`、`--repeats`、`--memory-repeats`，默认输入输出位置与 v2.0 一致，文件互不覆盖。
四组采用同一搜索实现及数据表示进行比较；v2.1 使用扁平数组保存代价与距离，执行速度应在本轮内部比较。
测试通过独立 Bellman-Ford 检查正反向地标距离、启发可采纳性与一致性、`h4≥h2≥h_scaled`、
免费终点、零地形、断连、索引重复查询、终点改变时重建，以及阶段测量的计数关系。

### 3.3：查看结果与测量口径

统一按 `(f, g, 坐标)` 排序，邻居顺序为上、下、左、右。三种算法每次搜索都转换地形代价矩阵并
扫描最小权重，这部分时间和内存计入测量。其余扩展计数、7 次计时和 3 次独立内存测量的口径与 Quiz1 相同。
独立反向 Dijkstra 重算最优代价，并核对地图的参考答案；每次运行检查路径累计进入代价、
端点、连续性、障碍、结果稳定性与输入未修改。同代价路径不要求具有相同的移动步数。

- `summary_v2.0.csv`：总体及规模、结构、非终点最小权重、密度、可达性等分组汇总。
- `results_v2.0.json`：完整路径、原始测量样本、汇总与环境信息。
- `performance_comparison_v2.0.png` / `.svg`：一张三联水平条形图的两种格式，依次比较扩展节点、耗时和峰值内存。

#### 单次查询与成本统计（v2.1）

本轮固定每张地图原有的起终点。每次预热、计时或内存测量都重新执行预处理，不跨查询缓存距离表，
两地标与四地标组也独立构建索引。输入终点改变时其免费进入边随之改变，应重新预处理。

- 预处理：地形转换、最小权重扫描、地标选择及正反向距离表构建；基础两组只做共同的地形转换和扫描。
- 查询：使用已准备的数据执行搜索、启发计算与路径恢复。
- 时间：每组合预热一次，独立重复 7 次。逐次记录预处理、查询及总时间，分别取中位数；总时间直接测量，
  不将两个阶段的中位数相加。各图表指标再跨地图等权平均。
- 内存：另测 3 次。记录预处理峰值、保留的预处理分配、含索引的查询峰值与查询新增峰值。
  总峰值取预处理峰值和含索引查询峰值的较大者；保留的分配包括地形矩阵及地标索引，不是索引文件大小。
- 扩展：`expanded_nodes` 仅计查询中的有效非终点扩展；距离表构建的扩展另记为
  `preprocessing_expanded_nodes`，两者之和为 `total_expanded_nodes`。

输出位于 `result/quiz2`，均带 `_v2.1`：

- `details_v2.1.csv`：420 项组合的最小代价、地标配置、查询扩展数以及各阶段时间和内存。
- `summary_v2.1.csv`：总体与规模、结构、权重、密度、可达性分组汇总，保留阶段指标。
- `results_v2.1.json`：完整路径、时间和内存的逐次阶段样本、环境和规则。
- `performance_comparison_v2.1.png` / `.svg`：同一张三联水平条形图，分别展示**查询扩展节点、包含预处理的总耗时、总峰值内存**。

## 4. quiz3：极大极小博弈树与 Alpha-Beta 剪枝

### 4.1：准备模拟博弈树

脚本覆盖同目录的 `map`，生成以下 **6 张固定手工地图**，不使用随机抽样：

| 用例 ID                    | 内容与用途                                     |

| `pass_through_treasures` | 单行地图，检查途经宝藏时只获取选中的目标       |
| `negative_gains`         | 负收益行动，检查正常选择和收益累计             |
| `symmetric_ties`         | 对称地图和相同价值，检查并列最优首步           |
| `weighted_detour`        | 障碍与高代价格子，检查低代价绕行               |
| `position_updates`       | 分散宝藏，检查第二次行动从玩家更新后的位置出发 |

数据采用 UTF-8 JSON，顶层 `cases` 保存地图，`primary_case_id` 指定主用例 `example_7x7`。
每个用例的 `grid` 是二维字符串列表，`T1` 等多字符标记占一个格子；`players` 保存双方坐标和角色，
`treasures` 保存宝藏坐标与价值，`initial_state` 保存位置、剩余宝藏、累计收益和当前玩家。
坐标从 0 开始。`expected` 包含独立 Dijkstra 的 6×6 距离矩阵，以及完整求值生成的

本题规则如下：

- 只能上下左右移动，`X` 不可通行；进入数字格支付其权重，进入 A、B、T 所在格支付 1。起点初始不收费，目标宝藏格收费。
- 按 A→B→A→B 行动，每次选一个剩余宝藏；净收益为负仍是合法行动。
- 获取后只更新当前玩家的位置、收益和选中宝藏的剩余状态。途经其他宝藏不自动获取，已获取宝藏格仍可通行且代价保持为 1。
- 另一玩家不阻挡路径。单次收益为 `Gain=Vi-D[pos,Ti]`，评价值为 `U=Score_A-Score_B`，A 最大化、B 最小化。
- `H` 按单次玩家行动计数；`H=2` 是双方各一次，`H=4` 是完整四次行动。到达深度上限或宝藏取完时，直接返回当前 `U`。

`H=2` 评价截断局面，`H=4` 评价最终局面，可据此分析短期决策与完整博弈的差异。
